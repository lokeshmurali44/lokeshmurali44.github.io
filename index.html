How I Work

From ambiguity
to shipped product.

The method flexes with the product, but the sequence stays deliberate: understand the system, make the problem clear, build shared direction and stay accountable through delivery.

Understand

Read the whole system.

I learn the business model, users, technology, risk and constraints before deciding what the interface should become.

Discovery / domain model / stakeholder alignment

Frame

Make the right problem visible.

I map roles, journeys, decisions and edge cases, then turn scattered inputs into a product direction the team can act on.

Problem frame / journeys / experience principles

Align

Build shared direction early.

Wireframes and prototypes help product, engineering, and stakeholders resolve uncertainty early.

Flows / wireframes / prototypes / decisions

Systemise

Design for the next release too.

I create reusable components, tokens and interaction rules that keep the product coherent as teams and feature sets grow.

UI direction / design system / interaction rules

Ship and learn

Stay accountable through production.

I work with engineers, review implementation, validate the experience and use AI-assisted frontend workflows when they shorten the path from approved design to working product.

Engineering review / UX QA / working frontend / iteration
